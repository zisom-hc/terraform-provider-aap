# aap_job (Data Source)

Get an existing AAP job.

Actions cannot return values, so a job launched by the `aap_job_launch`
action cannot be read from the action itself. This data source reads the job
back from the AAP API instead: either a job by `id`, or the most recent job of
a `job_template_id`, optionally narrowed to a `limit`.

`stdout` holds the job output as text.

Nothing found is a warning, not an error, so a plan that runs before a job has
ever been launched still succeeds.

## Example Usage

```terraform
terraform {
  required_providers {
    aap = {
      source = "ansible/aap"
    }
  }
}

provider "aap" {
  host     = "https://AAP_HOST"
  username = "ansible"
  password = "test123!"
}

# The most recent job of a job template.
data "aap_job" "latest" {
  job_template_id = 7
}

output "latest_job" {
  value = {
    status = data.aap_job.latest.status
    failed = data.aap_job.latest.failed
    stdout = data.aap_job.latest.stdout
  }
}

# The most recent job of a job template for one host.
data "aap_job" "latest_for_host" {
  job_template_id = 7
  limit           = "lx1-s4kl1rkhhst0012-app-01"
}

# A job by id.
data "aap_job" "by_id" {
  id = 7038
}
```

## Schema

### Optional

- `id` (Number) ID of the job. If not set, the most recent job matching the other attributes is read.
- `job_template_id` (Number) ID of the job template to read the most recent job of.
- `limit` (String) Only consider jobs launched with this limit pattern, for example a host name.

### Read-Only

- `elapsed` (Number) How long the job ran, in seconds.
- `failed` (Boolean) Whether the job failed.
- `finished` (String) When the job finished.
- `job_explanation` (String) Why the job is in its current state, as reported by AAP.
- `started` (String) When the job started.
- `status` (String) Status of the job: new, pending, waiting, running, successful, failed or canceled.
- `stdout` (String) Job output as text.
- `url` (String) URL of the job.
